Aperture Pay Payments API

Overview

Aperture Pay sits between your checkout and a customer’s funded wallet. Your server charges a wallet synchronously and receives an authoritative balance in the response. Final settlement — clearing funds and applying any incentives — happens asynchronously, and Aperture notifies your server through a signed webhook.

  • Requests you send to Aperture — charges, reversals, reads. You sign these with your secret.
  • Webhooks Aperture sends you — settlement and reversal outcomes. Aperture signs these; you verify them.

Charge lifecycle

flow
customer checkout
      │
      ▼
[1] POST /charges ────►  authorize against the wallet → 201 + balance
      │
[2] show result to the customer (succeeded / declined)
      │
[3] charge.settled  ◄──  Aperture webhook (async, signed) → funds cleared
      │
[4] reconcile in your ledger
Note

A charge that returns 201 is committed against the wallet immediately. The settlement webhook confirms clearing and carries the final figures — it does not re-authorize the charge.

Authenticating requests

Every request carries three headers. The signature is an HMAC-SHA256 of a canonical string built from the request, keyed by your API secret and base64-encoded.

HeaderDescription
Aperture-KeyPublishable key id, e.g. apk_live_8Qz…. Identifies the signing secret.
Aperture-TimestampUnix seconds at signing. Skew greater than ±300s is rejected.
Aperture-SignatureVersion-prefixed signature, e.g. v1=&lt;base64&gt;.

The canonical string

Concatenate four fields with a single newline between each, in order. The body hash is the lowercase hex SHA-256 of the raw body; for empty bodies, hash the empty string.

text
canonical =  METHOD            # POST
          + "\n" + PATH       # /v1/charges
          + "\n" + BODY_SHA256 # hex sha256 of raw body
          + "\n" + TIMESTAMP   # matches Aperture-Timestamp

signature = base64( HMAC_SHA256( api_secret, canonical ) )
header    = "v1=" + signature
Watch out

Sign the raw bytes you transmit. Re-serializing the JSON after signing changes the body hash and yields 401 signature_mismatch.

Verifying inbound webhooks

Inbound webhooks use the same construction, signed with your secret, in the Aperture-Webhook-Signature header. Rebuild the canonical string from the received request and compare with a constant-time check; reject anything outside the timestamp window.

Idempotency

Network failures make it impossible to know whether a charge committed. An idempotency key lets you retry safely — Aperture performs the operation at most once.

FieldTypeDescription
Idempotency-KeystringrequiredUnique per logical operation — a UUID is ideal. Reusing a key replays the original outcome.
  • The first request with a key executes and the result is stored for 24 hours.
  • A replay returns the original status and body plus Aperture-Idempotent-Replay: true — even if the original failed.
  • Reusing a key with a different body returns 409 idempotency_conflict.

Charges

Create a charge

Debits a customer wallet and returns the post-charge balance. Committed on a 201 response.

POST/v1/charges
FieldTypeDescription
wallet_idstringrequiredWallet to debit.
amountintegerrequiredMinor units, e.g. 2500 = €25.00.
currencystringrequiredISO 4217, lowercase, e.g. eur.
referencestringrequiredYour order reference. Max 80 chars.
capturebooleanoptionaltrue (default) settles now; false authorizes only.
metadataobjectoptionalUp to 20 string pairs, echoed on related objects and webhooks.

Retrieve a charge

GET/v1/charges/{charge_id}

Reversals

A reversal returns funds to the wallet and unwinds a charge — refunds, cancellations, or recovery from a failure on your side after a charge committed. Reversals are idempotent and may be partial.

POST/v1/charges/{charge_id}/reversals
FieldTypeDescription
amountintegeroptionalMinor units to return. Omit to reverse the full remaining amount.
reasonstringoptionalOne of requested_by_customer, duplicate, fraud, operator_recovery.
Watch out

Reversing a charge whose cashback already settled also claws back the cashback. The net movement is reported in balance_after and in reversal.completed.

Settlement webhooks

Aperture delivers events to your registered endpoint via signed POST. Return a 2xx within 8 seconds; anything else is a delivery failure and is retried.

EventWhen it fires
charge.settledFunds cleared. Carries final amounts and any applied cashback.
charge.failedA previously-succeeded charge could not clear. Reverse downstream effects.
reversal.completedA reversal finished clearing.
cashback.grantedA campaign credited cashback for one of your charges.
http
POST /your/webhook HTTP/1.1
Aperture-Webhook-Signature: v1=ZXZlbnQtc2ln…Qb8=
Aperture-Timestamp: 1733931120
Content-Type: application/json

{
  "id": "evt_5RcD8mK2",
  "type": "charge.settled",
  "data": {
    "charge_id": "chg_7H2nQ4xL",
    "amount": 2500,
    "cashback": { "campaign_id": "cmp_Wq1", "amount": 125 }
  }
}
Note

Webhooks are at-least-once. Deduplicate on event.id and keep handlers idempotent — a settled charge may be delivered more than once.

Delivery &amp; recovery

If your endpoint fails to acknowledge an event, Aperture retries on an exponential back-off. Each attempt re-signs with a fresh timestamp; the event.id is stable across attempts.

AttemptDelay after previousCumulative
1immediate0s
230s30s
32m~2m
410m~12m
51h~1h
66h~7h
7 (final)24h~31h

After the final attempt the event is marked undelivered. List and replay missed events:

GET/v1/events?status=undelivered
POST/v1/events/{event_id}/redeliver
Important

Do not gate checkout on the settlement webhook. The synchronous 201 from POST /charges is the source of truth for fulfilment; webhooks reconcile afterward.

Cashback campaigns

A campaign returns a percentage of qualifying charges to the wallet as cashback. Aperture evaluates campaigns automatically at settlement — you don’t compute incentives yourself.

POST/v1/campaigns
FieldTypeDescription
rate_bpsintegerrequiredCashback rate in basis points — 500 = 5%.
max_cashbackintegeroptionalPer-charge cap in minor units.
starts_atstringrequiredISO-8601 start.
ends_atstringrequiredISO-8601 end.
eligible_referencesarrayoptionalOnly charges whose reference has one of these prefixes qualify.

On settlement, the charge.settled webhook includes a cashback object and a cashback.granted event fires. Cashback is clawed back automatically if the charge is later reversed.

Error reference

Errors return a non-2xx status and a structured body. code is stable and safe to branch on.

HTTPcodeMeaning
400missing_parameterA required field is absent.
401signature_mismatchSignature did not match the canonical string.
401timestamp_out_of_rangeTimestamp skew exceeded ±300s.
402insufficient_fundsWallet balance below charge amount.
404resource_missingNo object with that id.
409idempotency_conflictKey reused with a different body.
429too_many_requestsSlow down; honour Retry-After.
500internal_errorTransient fault — safe to retry with the same idempotency key.

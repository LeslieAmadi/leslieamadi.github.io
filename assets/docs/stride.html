Overview

Stride runs automation workflows on your behalf. You start a run with a REST call; Stride executes it asynchronously and reports progress through signed events delivered to your webhook.

ChannelDirectionAuth
REST APIYou → StrideBearer token in Authorization.
WebhooksStride → YouSigned payloads you verify with a per-endpoint secret.
flow
queued ─► running ─► succeeded
               └─► failed ─► (optional) retried ─► running …

Each transition emits an event: run.started, run.step.completed, run.succeeded, run.failed.

API authentication

Authenticate REST calls with a secret API token as a bearer credential, scoped to a workspace and environment.

http
GET /v2/runs/run_8Kd2 HTTP/1.1
Host: api.stride.dev
Authorization: Bearer sk_live_3pQ9…vT
Important

Treat sk_live_ tokens as passwords — never ship them to a browser or mobile client. For front-end use, mint short-lived scoped tokens server-side via POST /v2/tokens.

Idempotent writes

Any request that starts a run accepts an Idempotency-Key so a retried POST never starts the same run twice.

  • First request with a key runs; its response is cached for 24 hours.
  • A repeat with the same key replays the cached response with Stride-Idempotent-Replay: true.
  • Same key, different body → 409 idempotency_conflict.

Retrieve a run

Polling is supported but secondary — webhooks are the intended way to learn about completion.

Webhooks

Stride POSTs events as they happen. Your endpoint must be public HTTPS and return any 2xx within 10 seconds; the body is ignored.

http
POST /your/webhook HTTP/1.1
Stride-Signature: t=1733930535,v1=4f8c2a…e90b
Content-Type: application/json

{
  "id": "evt_2Qa7",
  "type": "run.succeeded",
  "data": { "run_id": "run_8Kd2", "output": { "synced": 14 } }
}

Verifying the signature

Build the signed payload as t, a literal dot, and the raw body. HMAC-SHA256 it with the endpoint secret and compare in constant time.

text
signed_payload = t + "." + raw_body
expected       = hex( HMAC_SHA256( signing_secret, signed_payload ) )
# accept if expected == v1  AND  now - t <= 300 seconds
Watch out

Verify against the raw bytes before any JSON parsing. Frameworks that hand you a re-serialized object produce a different hash and fail verification.

Delivery &amp; retries

Stride guarantees at-least-once delivery. Duplicates and out-of-order events are possible.

  • Deduplicate on event.id.
  • Order by created_at and run state, not arrival time.
  • Make handlers idempotent — applying an event twice equals applying it once.

Usage &amp; credits

Runs consume credits from the workspace balance. Read it to surface usage or gate work before starting it.

GET/v2/usage/credits
json
{
  "balance": 8420,
  "included_monthly": 10000,
  "resets_at": "2026-01-01T00:00:00Z",
  "low_balance_threshold": 500
}

Crossing low_balance_threshold emits a credits.low event so you can prompt an upgrade before runs start failing with 402 insufficient_credits.

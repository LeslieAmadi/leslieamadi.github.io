Kestrel SDK: iOS Quickstart

Integrate a rewarded-advertising SDK into an iOS application: add the package, configure SKAdNetwork, request tracking authorisation at a moment when the system will actually show the prompt, initialise at launch, avoid the delegate retain cycle, and grant the reward only when it has been earned.

About this sample. Kestrel is a fictional advertising SDK written for this documentation piece. The API is invented, but the integration patterns, platform constraints and failure modes reflect how real iOS ad SDKs behave. The Android equivalent is here.

Requirements

This quickstart integrates Kestrel into an iOS application: add the package, initialise at launch, preload a rewarded ad, display it on demand, and grant in-game currency when the user earns a reward.

Before you start, you need:

  • Xcode 16 or later.
  • An iOS application targeting iOS 15.0 or above.
  • A Kestrel application ID from the developer dashboard.
  • A physical device for testing. The simulator has no IDFA and will not show the tracking prompt.
No network permission is required. Unlike Android, iOS grants outbound network access by default. There is no equivalent of <uses-permission android:name="android.permission.INTERNET" />.

1. Add the package

In Xcode, choose File › Add Package Dependencies and enter the Kestrel repository URL:

Package URL
https://github.com/kestrel-ads/kestrel-ios

Set the dependency rule to Up to Next Major Version from 1.0.0, then add the KestrelAds library to your app target.

For a package-based project, declare it in Package.swift instead:

Package.swift
dependencies: [
    .package(
        url: "https://github.com/kestrel-ads/kestrel-ios",
        from: "1.0.0"
    )
],
targets: [
    .target(
        name: "MyApp",
        dependencies: [
            .product(name: "KestrelAds", package: "kestrel-ios")
        ]
    )
]
Expected result. import KestrelAds resolves and the project builds.

2. Configure Info.plist

Two entries are required. Open Info.plist as source and add:

Info.plist
<key>KestrelAppID</key>
<string>YOUR_KESTREL_APP_ID</string>

<key>NSUserTrackingUsageDescription</key>
<string>This identifier will be used to show you more relevant rewarded offers.</string>

<key>SKAdNetworkItems</key>
<array>
    <dict>
        <key>SKAdNetworkIdentifier</key>
        <string>kestrel1a2b.skadnetwork</string>
    </dict>
</array>
KeyPurpose
KestrelAppID Identifies your app to Kestrel. Safe to ship.
NSUserTrackingUsageDescription The text shown in the tracking prompt. Without this key the prompt never appears and the app is rejected at review.
SKAdNetworkItems Ad-network identifiers used for install attribution. Missing entries mean installs go unattributed and revenue is undercounted.
Do not embed server credentials. An application ID identifies your app and is safe to ship. Private keys are not: Info.plist is readable in any unpacked .ipa.

3. Initialise at launch

Kestrel initialises once per app launch. The place for that is application(_:didFinishLaunchingWithOptions:), which runs before any interface appears.

SwiftUI apps reach the app delegate through an adaptor:

MyApp.swift (SwiftUI)
import SwiftUI
import KestrelAds

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) private var appDelegate

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

final class AppDelegate: NSObject, UIApplicationDelegate {

    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions:
            [UIApplication.LaunchOptionsKey: Any]? = nil
    ) -> Bool {

        KestrelAds.setLogLevel(.debug)
        KestrelAds.initialize()

        return true
    }
}

UIKit apps already have one:

AppDelegate.swift (UIKit)
import UIKit
import KestrelAds

@main
final class AppDelegate: UIResponder, UIApplicationDelegate {

    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions:
            [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {

        KestrelAds.setLogLevel(.debug)
        KestrelAds.initialize()

        return true
    }
}

Set the log level before initialising, or initialisation itself produces no output. Disable debug logging in release builds.

Warning 1 — initialise once, at launch. Do not initialise Kestrel in viewDidLoad() or .onAppear. A view controller is created and destroyed as the user navigates, and .onAppear fires again every time a SwiftUI view returns to screen, so the SDK would initialise repeatedly.

4. Request tracking authorisation

Rewarded advertising uses the advertising identifier (IDFA). Since iOS 14.5, reading it requires the user's permission through App Tracking Transparency.

TrackingAuthorization.swift
import AppTrackingTransparency
import KestrelAds

enum TrackingAuthorization {

    /// Call only when the app is in the foreground and active.
    static func request() {
        ATTrackingManager.requestTrackingAuthorization { status in
            // Kestrel serves ads regardless of the outcome.
            // Denied authorisation means contextual rather than
            // personalised ads, and lower revenue per impression.
            KestrelAds.setTrackingAuthorizationStatus(status)
        }
    }
}

Call it once the app is genuinely active, not during launch:

ContentView.swift
import SwiftUI

struct ContentView: View {
    @Environment(\.scenePhase) private var scenePhase
    @State private var hasRequestedTracking = false

    var body: some View {
        RewardedAdView()
            .onChange(of: scenePhase) { _, newPhase in
                guard newPhase == .active, !hasRequestedTracking else { return }
                hasRequestedTracking = true
                TrackingAuthorization.request()
            }
    }
}
Warning 2 — the prompt fails silently before the app is active. Calling requestTrackingAuthorization from didFinishLaunchingWithOptions returns .denied immediately without ever showing the prompt. There is no error and nothing in the log. The app is still in the .inactive state, and the system discards the request. Wait for .active.

The user can only be asked once per install, so a request lost this way is lost for good until the app is deleted and reinstalled.

5. Load and show a rewarded ad

Preload the ad when the screen appears so the user never waits after tapping. The flow is:

  1. Create a KestrelRewardedAd and assign the delegate.
  2. Request the ad. Keep the button disabled while it loads.
  3. Enable the button in rewardedAdDidLoad(_:).
  4. Present the preloaded ad when the user taps.
  5. Grant the reward in rewardedAd(_:didEarnReward:), never in rewardedAdDidDismiss(_:).
  6. Load the next ad after dismissal.
  7. Retry transient failures with bounded exponential backoff.

Kestrel delivers delegate callbacks on a background queue, so every UI update is dispatched to the main queue.

RewardedAdViewController.swift
import UIKit
import KestrelAds

final class RewardedAdViewController: UIViewController {

    @IBOutlet private weak var coinBalanceLabel: UILabel!
    @IBOutlet private weak var watchAdButton: UIButton!
    @IBOutlet private weak var retryButton: UIButton!

    private var coins = 0
    private var rewardedAd: KestrelRewardedAd?
    private var adReady = false

    private var retryCount = 0
    private var retryWorkItem: DispatchWorkItem?
    private let maxRetries = 3

    override func viewDidLoad() {
        super.viewDidLoad()

        watchAdButton.isEnabled = false
        retryButton.isHidden = true

        updateCoinBalance()
        loadRewardedAd()
    }

    deinit {
        retryWorkItem?.cancel()
        rewardedAd?.delegate = nil
    }

    // MARK: - Loading

    private func loadRewardedAd() {
        adReady = false
        watchAdButton.isEnabled = false

        let ad = KestrelRewardedAd()
        ad.delegate = self
        rewardedAd = ad
        ad.load()
    }

    private func scheduleRetry() {
        guard retryWorkItem == nil else { return }

        guard retryCount < maxRetries else {
            retryButton.isHidden = false
            return
        }

        let delay = 2.0 * pow(2.0, Double(retryCount))
        retryCount += 1

        let work = DispatchWorkItem { [weak self] in
            self?.retryWorkItem = nil
            self?.loadRewardedAd()
        }
        retryWorkItem = work
        DispatchQueue.main.asyncAfter(deadline: .now() + delay, execute: work)
    }

    // MARK: - Actions

    @IBAction private func watchAdTapped(_ sender: UIButton) {
        guard adReady, let ad = rewardedAd else { return }

        adReady = false
        watchAdButton.isEnabled = false
        ad.present(from: self)
    }

    @IBAction private func retryTapped(_ sender: UIButton) {
        retryCount = 0
        retryButton.isHidden = true
        loadRewardedAd()
    }

    private func updateCoinBalance() {
        coinBalanceLabel.text = "Coins: \(coins)"
    }
}

// MARK: - KestrelRewardedAdDelegate

extension RewardedAdViewController: KestrelRewardedAdDelegate {

    func rewardedAdDidLoad(_ ad: KestrelRewardedAd) {
        DispatchQueue.main.async { [weak self] in
            guard let self, self.rewardedAd === ad else { return }

            self.retryCount = 0
            self.adReady = true
            self.watchAdButton.isEnabled = true
            self.retryButton.isHidden = true
        }
    }

    func rewardedAd(_ ad: KestrelRewardedAd, didEarnReward amount: Int) {
        DispatchQueue.main.async { [weak self] in
            guard let self else { return }

            self.coins += amount
            self.updateCoinBalance()
        }
    }

    func rewardedAdDidDismiss(_ ad: KestrelRewardedAd) {
        DispatchQueue.main.async { [weak self] in
            guard let self, self.rewardedAd === ad else { return }

            self.rewardedAd = nil
            self.adReady = false
            self.loadRewardedAd()
        }
    }

    func rewardedAd(_ ad: KestrelRewardedAd, didFailToLoad error: Error) {
        DispatchQueue.main.async { [weak self] in
            guard let self, self.rewardedAd === ad else { return }

            self.rewardedAd = nil
            self.adReady = false
            self.watchAdButton.isEnabled = false
            self.scheduleRetry()
        }
    }
}

Four details in that listing are worth noticing. [weak self] in every closure prevents the view controller being kept alive by a pending callback. The rewardedAd === ad check means a late callback from a discarded instance cannot change the current state. Retries back off at two, four and eight seconds and then stop, revealing a manual retry button rather than leaving a dead control. And deinit cancels the pending retry and clears the delegate.

Warning 3 — the delegate must be weak. Kestrel declares weak var delegate, so assigning self does not create a retain cycle. If you write your own object that holds an ad strongly while the ad holds it back strongly, neither is ever deallocated: Swift uses reference counting, not garbage collection, so a cycle leaks silently. Clearing the delegate in deinit is cheap insurance.
Warning 4 — update the UI on the main queue. UIKit and SwiftUI may only be touched from the main queue. Kestrel's callbacks arrive on a background queue, so every UI update goes through DispatchQueue.main.async. Touching a view from a background queue produces undefined behaviour: often a crash, sometimes a layout glitch that appears only on a slower device.

6. Grant the reward

Kestrel reports two separate events, and the difference between them matters commercially:

CallbackFires whenGrant the reward?
rewardedAd(_:didEarnReward:)The user completed the eligible interaction.Yes
rewardedAdDidDismiss(_:)The ad closed, whether completed or skipped.No
Warning 5 — never grant on dismissal. rewardedAdDidDismiss(_:) fires whether the user watched the ad or quit after two seconds. Granting coins there teaches users to open an ad and immediately close it: the publisher pays out rewards nobody earned, and the advertiser is billed for impressions nobody saw.

The coins property in the sample lives in memory on the device. A production rewards system should hold the authoritative balance on a trusted backend, verify the reward event server side where supported, and make reward processing idempotent so the same event cannot credit an account twice.

7. Test the integration

Test on a physical device. The simulator has no advertising identifier and will not present the tracking prompt, so an integration that looks correct there can still fail on hardware.

ScenarioExpected result
App launchesKestrel initialises once; debug logs appear in the console.
App becomes activeThe tracking prompt is presented, once per install.
Tracking is deniedAds still load and rewards still work.
Ad is loadingWatch Ad stays disabled.
Ad loadsWatch Ad becomes available.
User taps Watch AdThe preloaded ad presents with no wait.
User completes the adCoin balance increases by the reported amount.
User closes earlyNo reward is granted.
Load fails onceA retry is scheduled after two seconds.
Load fails four timesAutomatic retries stop; the manual retry button appears.
User leaves the screen mid-retryThe view controller deallocates; no callback fires into it.

Test the early-close case deliberately. An integration that grants rewards on dismissal looks identical to a correct one until someone notices the payout figures.

To confirm there is no retain cycle, navigate away from the screen and check that deinit runs. Use the Memory Graph Debugger in Xcode if it does not.

Troubleshooting

SymptomLikely cause
The tracking prompt never appears Requested before the app reached .active, NSUserTrackingUsageDescription is missing, the user already answered, or you are on the simulator.
Package fails to resolve Wrong URL, a version rule excluding all releases, or stale package state. Reset via File › Packages › Reset Package Caches.
The ad never becomes available Wrong KestrelAppID, no network, or the delegate was deallocated before the callback arrived.
Crash or layout glitch after a callback A view is being updated from the background queue. Dispatch to main.
The SDK initialises repeatedly Initialisation is in viewDidLoad() or .onAppear rather than the app delegate.
The view controller is never deallocated A retain cycle. Check for a strong delegate reference and for closures capturing self strongly.
Users get rewards after closing early Reward logic is in rewardedAdDidDismiss(_:) instead of rewardedAd(_:didEarnReward:).
Installs are unattributed SKAdNetworkItems is missing the Kestrel identifier.
No debug logs setLogLevel(_:) runs after initialize().

Writer's note

About this piece

Kestrel does not exist. I wrote the Android and iOS quickstarts as a pair to work through where the platforms genuinely diverge, rather than translating one into the other and changing the syntax.

Two of the five warnings here have no Android equivalent. The retain cycle exists because Swift counts references instead of collecting garbage, so a delegate held strongly in both directions leaks in silence. And the tracking prompt discards a request made before the app is active — no error, no log, and the user cannot be asked again until they reinstall. Both are invisible failures, which is why they are callouts rather than prose: the ones that crash get found, and the ones that quietly do nothing do not.

How the integration works

The operator owns the player’s money; Helix owns the game logic. They meet at two surfaces: the operator opens a play session and redirects the player to the game client; as the player plays, Helix calls the operator’s wallet hook for every round.

TermMeaning
Play sessionOne player, one game, one currency. Created by the operator; session_id.
RoundA single interaction that moves money: a stake out and/or a return in.
Wallet hookThe operator endpoint Helix calls per round. The reply decides whether the round stands.
Reversal hookThe operator endpoint Helix calls to unwind a round that can’t be confirmed.
ledger_refGlobally unique id Helix assigns to a round — the key the operator stores to reconcile reversals.
flow
operator                         Helix RGS                       player
   │  POST /sessions  ──────────►│
   │  ◄────── session + client_url
   │  redirect player to client_url ──────────────────►│ spins
   │  ◄── wallet hook (stake/return for the round) ─────│
   │  reply: new balance ───────►│ result shown ──►│

Request signing

Helix uses HTTP message signatures. Both sides sign. A request carries a Digest of its body and a Signature header naming exactly which fields were signed.

HeaderDescription
Helix-DateRFC 1123 timestamp. Requests outside ±60s are rejected.
DigestSHA-384=&lt;base64&gt; of the raw body.
SignatureNames keyId, algorithm, ordered headers, and the signature.

Building the signing string

Emit each listed field as name: value on its own line, joined by newlines. (request-target) is the lowercase method, a space, then the path. HMAC-SHA384 with the operator secret; base64 the result.

text
(request-target): post /2024-09/sessions
helix-date: Wed, 11 Dec 2025 14:00:15 GMT
digest: SHA-384=Yk9u…q2A=

signature = base64( HMAC_SHA384( secret, signing_string ) )
Note

Reject a hook whose Digest doesn’t match a fresh hash of the received body, then verify the signature over the named headers with a constant-time compare. Order matters.

The wallet hook

For every round Helix POSTs to your wallet_hook (signed). Apply the movement and reply with the new balance — or decline with a reason. Reply 200 within 10 seconds.

FieldTypeDescription
ledger_refstringrequiredUnique id of this round. Store it — reversals reference it.
stakeintegerrequiredMinor units to remove (may be 0).
returnintegerrequiredMinor units to add (may be 0).
feature_cycleobjectrequiredroot_ref plus closes — whether the cycle ends here.

Confirming a round

Compute balance &minus; stake + return, guarding against a negative result before applying the return.

json
{ "balance": 49750, "ledger_ref": "lr_4Np7Kq2" }
Watch out

Persist the round against its ledger_ref in the same transaction that moves the money. If you can’t look a round up later, you can’t safely process its reversal.

Failure &amp; recovery

A wallet hook can fail technically or simply not arrive. Helix offers two recovery modes per operator.

ModeOn a technical failureBest for
compensate (default)The round is unwound via your reversal_hook; the player may resume once it succeeds.Operators whose ledger can reverse an applied movement.
settleThe round is held and the wallet hook is retried until it succeeds; play locks meanwhile.Operators who cannot reverse and prefer eventual consistency.

The reversal hook

In compensate mode Helix POSTs the original round body to your reversal_hook, keyed by the same ledger_ref. Undo any movement and reply with the corrected balance.

Note

If you never saw the original hook, there’s nothing to undo — make no change and reply with the current balance and same ledger_ref. Reversals must be safe to receive more than once.

Bonus-round promotions

A promotion grants fixed-stake bonus rounds in a chosen game. While active, wallet hooks carry a promotion object so you can account for bonus play separately.

POST/2024-09/promotions/bonus-rounds
FieldTypeDescription
game_codestringrequiredThe single game the bonus rounds run in.
stake_per_roundintegerrequiredFixed stake per bonus round. Must be a valid bet step.
roundsintegerrequiredBonus rounds granted to each player.
playersarrayrequiredEligible player_ref values.
Note

Whether bonus stakes draw from the real wallet is the operator’s decision. If you don’t deduct them, treat the hook’s stake as informational and reply with the unchanged balance.

Error reference

Errors returned to the operator use a stable code. These are distinct from wallet-hook decline.reason values, which the operator sends to Helix.

HTTPcodeMeaning
401signature_invalidSignature did not verify over the named headers.
401digest_mismatchBody digest did not match the request body.
401date_skewHelix-Date outside the ±60s window.
404game_unknownNo game with that game_code.
409session_lockedA pending reversal or settle is blocking the session.
422hook_urls_identicalWallet and reversal hooks must differ.
500rgs_errorTransient server fault — safe to retry.
